# 比赛答辩常见问答

## 1. 这是不是只给旧内容生成项目改了名字？

不是简单改名。项目保留了图片、视频、数字人、音乐和剪辑等可复用生产能力，但新增了跨境商品录入、目标市场、合规规则库、RAG 检索、多 Agent 工作流、Critic 评审、一键创建营销项目、工作台和数据分析闭环。内部 `dramas/episodes/storyboards` 表名暂时保留，是为了降低迁移风险。

## 2. 多 Agent 是一个 Prompt 里假装多个角色吗？

不是。Planning、Product、Compliance、Localization、Content、Critic 分阶段顺序执行，每阶段有独立输入、Prompt、结构化输出和 AgentTrace。Critic 低分时最多触发一次 Content 修订，再复评，避免无限循环。

## 3. 合规 RAG 用了向量数据库吗？

当前比赛版本使用轻量 JSON 规则库和关键词/国家/平台/类目匹配，强调稳定和可解释。命中规则会进入 ComplianceAgent 上下文并随结果返回。后续可把 SearchRules 接口替换为向量检索，不影响工作流结构。

## 4. 合规结果能作为法律结论吗？

不能。系统固定提示“仅用于跨境电商营销合规辅助，不构成法律意见”，正式上架还需复核当地法规、平台政策、检测报告和专业意见。

## 5. 数据分析是真实广告数据吗？

目前不是。当前指标基于平台内项目、素材、视频、合成和分发记录估算，页面已明确标注。广告花费、订单、店铺销售额和真实转化率需要接入 Amazon、TikTok Shop、Shopee 等平台 API。

## 6. Demo 数据是不是假装真实业务数据？

不是。Seed 项目、素材、Agent 历史和数字人错误任务均带 `[DEMO]`、`demo-seed` 或明确边界说明。Seed 不调用第三方 AI，也不会创建虚假的广告订单、销售额或数字人成功视频。

## 7. 没有模型 Key 能演示什么？

可以演示项目、规则合规、历史结果、脚本、素材管理、数字人任务状态、工作台和分析数据流。Agent 调试模式可能返回明确标识的本地兜底；图片、视频和数字人真实生成会返回配置缺失或供应商错误，不伪造成功。

## 8. 为什么默认用 SQLite？

SQLite 降低比赛部署和单机演示门槛，已启用 WAL、busy timeout 和单写连接限制。多实例、高并发生产环境建议切换 MySQL，并引入 Redis/消息队列承载异步任务。

## 9. 如何保证 Demo 稳定？

固定商品、固定 Demo 设备 ID、幂等 seed、Agent 历史回放、smoke test、前后端构建检查和明确的联网失败回退路径。现场实时生成是增强项，不是唯一展示路径。

## 10. 第三方密钥如何保护？

后端密钥通过 `.env` 或部署平台 Secret 注入，示例文件只保留空值。AI 服务配置目前保存在数据库，生产阶段需要进一步加密、权限隔离和密钥轮换。前端只保存匿名设备 ID，不应包含供应商密钥。

## 11. 当前最大的技术边界是什么？

真实平台数据、生产级用户与权限、多租户隔离、任务队列、供应商计费控制、日志监控和失败重试体系仍需增强。旧内部命名也需要在数据迁移方案成熟后逐步清理。

## 12. 下一阶段如何扩展？

优先接入真实店铺/广告数据，升级合规向量检索，引入队列和对象存储，增加供应商路由与成本控制，最后完成账号权限、审计、监控和多实例部署。
